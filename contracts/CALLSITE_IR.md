# Minimal versioned callsite/binding IR and Python pilot

Contract: `callsite-ir-v1`. Resolves H08. Exact shapes: CallsiteBatch, Callsite, CallBinding, CallArgument, ExpressionRef and CallRange in `schemas/hardening-v1.schema.json`. The current LanguageAdapter at harness 0989172 returns symbols and generic relationships; it does **not** implement this IR. This is a small additive adapter capability, not a universal program-analysis framework.

## CI-R01 — Capability boundary

Keep inventory(path,bytes) and existing symbol/relationship IDs. Add an optional protocol `extract_calls(path: str, content: bytes, inventory: InventoryResult, *, start_byte: int = 0, max_calls: int = 10000) -> AdapterCallsiteBatch` behind a versioned capability registration. The adapter implementation may reuse its already-parsed syntax tree within the same indexing invocation; do not make another model parse the file. If no compatible capability exists, store UNSUPPORTED with a reason. A successful symbol inventory does not imply operation extraction succeeded.

The adapter returns the exact AdapterCallsiteBatch/AdapterCallsite/AdapterCallBinding shapes, with local symbol IDs and next_start_byte, not invented host snapshot/file IDs or host-authenticated cursors. The host wrapper maps every local ID through the same InventoryResult-to-index identity map, injects snapshot/file identity, creates callsite IDs and an authorized continuation, and emits the persisted CallsiteBatch. Unknown local IDs are a contract error, not silently dropped. Recheck the adapter file hash against the verified input before persistence. A module-level call uses containing_symbol_id null; do not fabricate a function or silently omit it. Mapping to one existing symbol is deterministic containment, with ambiguity reported.

## CI-R02 — Source-derived shape

CallRange uses zero-based original-byte half-open ranges, nonempty for call/expression ranges. Preserve encoding/newlines and original file hash. Every range must be inside the captured file and each argument/callee/receiver range must be inside its callsite. A CallArgument records source-order ordinal, POSITIONAL/KEYWORD/STAR/DOUBLE_STAR kind, nullable keyword identifier, expression reference and nullable literal boolean. Ordinary source strings, credential literals and evaluated arguments are not copied into the IR.

callee and receiver retain structural references (NAME, ATTRIBUTE, CALL, SUBSCRIPT, LITERAL, OTHER). `constant_bool` may be populated only for an actual boolean literal; a variable, integer 0/1, function result or expression remains null. This permits modeling shell=True/False without pretending to evaluate arbitrary code. More literal roles require a separately versioned extension, not an untyped metadata dictionary.

Binding state is EXACT, AMBIGUOUS, UNRESOLVED or NOT_SUPPORTED with an explicit basis. EXACT names a trusted canonical_api registry identity; spelling alone never qualifies. Ambiguous targets retain only alternatives actually produced by the resolver. Unknown receiver types and dynamic attribute/callback dispatch remain unresolved. A generic `.execute()` is not automatically a database/process sink.

The initial serialized batch holds at most 10000 callsites and 256 arguments per call. A call with more arguments remains visible with arguments_complete=false and LIMIT_ARGUMENTS; it cannot acquire semantics that require omitted roles. Larger batches are paginated by deterministic source order through the indexing owner. The adapter uses the full immutable file for parsing/binding on each continuation, then returns callsites starting at or after start_byte; next_start_byte is the next unreturned callsite start, never a substring parser boundary. Distinct calls sharing a start must be returned together or bounded by the existing indexed ordinal in the host adapter wrapper; the wrapper must not skip a call using byte-only ambiguity. If a start-position group itself exceeds max_calls, return an explicit PARTIAL/LIMIT_POSITION_GROUP instead of claiming completion. A per-file pass completes only after all batches/limitations are committed. Explicit PARTIAL/ERROR differs from no calls.

## CI-R03 — Stable identity and persistence

Derive callsite_id as `cs1:` plus H("ssr.callsite.v1", snapshot_id,file_id,file_hash,call_start,call_end,adapter_id,adapter_version). Exact reruns produce the same ID. Operation observation identity additionally includes operation-model version/facet; registry changes do not rewrite the old callsite or observation. Parser/model identities are distinct.

Prepare original-byte ranges and shape validation before opening the project transaction. Persist the file's IR generation, call rows, argument references, binding basis and limitations atomically per complete batch, with pass status PARTIAL until the final batch commits. Associate explicit operation observations with those existing callsites. Do not create a worker/candidate for every observation. On restart resume the same pass identity; conflicting payload at an existing ID is an integrity error.

The operation registry consumes this typed capability, not a nonexistent adapter.callsite_records method. It may assign semantics only when required binding and argument roles are available. A lexical match remains lexical discovery evidence and cannot be upgraded because the symbol table happens to contain one matching declaration.

## CI-R04 — First supported language and conservative binding rules

The first acceptance target is Python, using source parsing only, with no target imports, decorators or user configuration executed. The reference pilot in tools/contract_reference.py demonstrates the binding cases below; it is a contract fixture, not the production LanguageAdapter.

Support direct module-level `import subprocess as ps` and `from subprocess import run as launch` aliases and ordinary function bodies referring to an unshadowed module alias. Recognize only explicitly modeled subprocess members. All same-scope binders must be considered: assignments, annotated/augmented assignment, import aliases, parameters, function/class definitions, loop/with/except targets, pattern captures, named expressions and deletions. Binding forms not handled by the pilot/production resolver are explicit limitations, not ignored evidence of no shadowing.

An assignment/parameter binding to `ps` in a function invalidates reliance on a global `ps` alias throughout that lexical function scope, including a call appearing before the assignment. Conditional imports, reassignments, wildcard imports, global/nonlocal declarations, nested closure changes, comprehension/lambda scopes and dynamic getattr are unresolved unless a separately proven lexical rule handles them. Conservative false unknowns are acceptable; false EXACT bindings are not.

Order positional and keyword/star entries by their real source start (Python AST stores them in separate lists). For shell mode accept only an explicit boolean keyword with no **kwargs expansion that could affect the call; otherwise mark UNKNOWN. Duplicate/invalid argument syntax produces a parser error, not a successful operation result. Parse-error source remains available for authorized manual analysis, without fabricated IR.

Initial coverage matrix: Python direct/aliased subprocess calls and literal shell flag are the proven pilot; Python dynamic/shadowed/unsupported scope forms are explicit unknowns; all other languages/frameworks have callsite capability NOT_SUPPORTED until their own fixtures pass. Their generic symbols, source reads and analyst-led review continue. Do not claim broad multi-language argument semantics from generic relationships alone.

## CI-R05 — Implementation steps and acceptance

Add the typed optional capability and strict schema/range validator first. Integrate the Python adapter's syntax-tree/range conversion and lexical binder collector; store IR generation and diagnostics; implement the subprocess model over the typed roles; expose bounded operation queries; then extend other families/languages only with capability-specific tests. Reuse the existing inventory transaction owner, source verifier and operation/security-tag store. No alternate parser database, target execution or manager model is introduced.

CI-T01 direct and aliased subprocess.run; CI-T02 from-import alias; CI-T03 parameter and local assignment shadowing including assignment after call; CI-T04 generic execute receiver remains unresolved; CI-T05 shell literal true/false versus dynamic/expanded arguments; CI-T06 two calls on one line have distinct IDs/ranges; CI-T07 UTF-8 text before a call preserves original byte positions; CI-T08 module-level call has null containing symbol; CI-T09 malformed source records ERROR; CI-T10 conditional/wildcard/nested unsupported binding is not EXACT; CI-T11 deterministic rerun keeps IDs; CI-T12 registry version changes only observation generation; CI-T13 more than 256 arguments exposes partiality; CI-T14 unsupported language never becomes clean operation coverage. The release support table is generated from passing production adapter cases, not copied from the proposed catalogue.
