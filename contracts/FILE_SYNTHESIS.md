# Bounded file synthesis: immutable manifest, staged decisions, small seal

Contract: `synthesis-v1`. Resolves H02. Owners: P4-F02 canonical publication, P1-F03 normalization, P1-F08 operation recovery. The 65536-byte whole-tool-input ceiling remains; this contract removes repository-sized arrays from the model's terminal input instead of increasing that ceiling.

## SY-R01 — Host manifest is the complete mechanical input

After all required review units have accepted dispositions and their own required receipts, the canonical file owner builds an immutable manifest. Its header binds review/snapshot/file, file hash, graph/inventory generation, policy hash, parent input revision and format version. Its ordered rows contain every unit and selected accepted contribution/adoption receipt, complete dependency/SCC disposition, evidence closure reference, registered lead origin and unresolved reconciliation obligation. Children are referenced by immutable ID/hash, not copied source or bodies.

Use existing canonical contribution selection/validators, not a new result-selection model. Host-selected unchanged pass-through contributions preserve their complete semantics and provenance. The manifest must not label a missing child accepted or decide a disputed analytical merge. A manifest root is `H("ssr.synthesis-manifest.v1", header + ordered row digests)` using the canonical length-framed sequence defined below; compute it in bounded pages. Persist manifest rows once, freeze the header/root, and index `(manifest_id,ordinal)` and `(manifest_id,item_key)` uniquely.

The model receives only manifest ID/hash, counts, its file assignment, and a paged reconciliation queue. No terminal schema requires all symbol dispositions, all evidence IDs, or all lineage to be echoed by the model. An unmodified contribution is inherited through the host's exact manifest, not inferred from a missing model field.

The exact header and item rows are `$defs.SynthesisManifest` and `SynthesisManifestItem`. Header roots are computed by streaming canonical item rows ordered by ordinal through the same length-framed chain under `ssr.synthesis-manifest-items.v1`; required keys are separately sorted by UTF-8 bytes and chained under `ssr.synthesis-obligations.v1`. Empty roots use H(domain,[]). `manifest_hash = H("ssr.synthesis-manifest.v1", header)` binds those roots and complete counts. A CONTRIBUTION row requires nonnull unit/artifact identities and hashes; obligation rows require a nonnull unique decision key. `file:residual-analysis` is a RESIDUAL_FILE_OBLIGATION. Every item key/ordinal is unique; the host verifies all FK/ownership and root/count invariants before freezing. File-manifest queries return header plus bounded item pages, never the entire large set.

## SY-R02 — Session identity and immutable journal

Create one active session per `(parent_task_id,input_revision_hash,manifest_hash)`. Session identity and current journal revision are host-issued. Revision zero has `journal_hash = H("ssr.synthesis-journal.v1", {session_id,manifest_hash,input_revision_hash})`. A stage appends canonical entries under `head_next = SHA256(b"ssr.synthesis-entry.v1\0" + previous_head_bytes + revision.to_bytes(8,"big") + len(entry_bytes).to_bytes(8,"big") + entry_bytes)`; each committed entry increments revision once. Neither hidden worker memory nor model-created UUIDs determine progress.

Source-free journal entries have exact schemas `$defs.SynthesisDecision` or `$defs.SynthesisReferences`. The stage envelope is `$defs.SynthesisStage`. A stage has 1–32 entries and at most 65536 encoded UTF-8 bytes including input_token and envelope. Validate each entry and total bytes before starting the write transaction. Stage response is `$defs.SynthesisReceipt`: bounded identity, new revision/root, entry count and operation ID.

Large origin/evidence sets use REFERENCE_SET_PAGE entries with a session-local set_key, page_index starting at zero, 1–128 typed references, and final_page. Pages must be contiguous before the set is consumable. A set may not receive pages after its final page; contradictory duplicate pages are rejected. The full set identity is derived from session/set_key/ordered page hashes. No one model input carries the entire set. A terminal synthesis does not depend on an arbitrary fixed maximum number of units or deltas fitting in one message.

## SY-R03 — What the model actually decides

DECISION keys address existing reconciliation obligations or the reserved file-analysis obligation. A decision specifies RETAIN, MERGE, REJECT_PROPOSAL, UNRESOLVED, or FILE_ANALYSIS, explicit origin/evidence set keys when needed, rationale and nullable supersedes_digest. Unknown keys, missing referenced sets, unauthorized artifact refs and invalid action/key combinations are errors. Every action retains origin/provenance. REJECT_PROPOSAL rejects a suspicion, not a required unit's coverage. A MERGE must identify all merged origins and source-backed rationale; host code cannot infer that two similar texts are equivalent.

The host adds an obligatory `file:residual-analysis` key, even when no candidate conflict exists, so synthesis still performs cross-symbol reconciliation. Conflicting contributions create mandatory keys. All required keys must have a current valid decision before sealing. Optional unchanged child selections need no per-unit model acknowledgment. An explicit unresolved analytical conflict may satisfy its reconciliation obligation only by being recorded as UNRESOLVED with scope/limits; it cannot promote a disputed candidate or be presented as a conflict-free conclusion.

Accepted journal entries are immutable. To correct an earlier DECISION, append a new entry with supersedes_digest equal to the exact active prior entry. The active-decision projection uses a compare-and-swap; silently overwriting the old entry is forbidden. The journal root covers both versions. Reference-set pages do not support edits; a changed set uses a new set_key and an explicit replacement decision.

Use registered independent lead origin IDs from the manifest to avoid duplicating seeds. A new independent suspicion is reported through report_lead, then explicitly referenced; staged synthesis is not an unbounded alternative lead admission path.

## SY-R04 — Stage transaction and producer proof

Prepare source/reference/domain checks outside the write lock. Within the canonical owner's short transaction: revalidate exact task/attempt/input and session state; recover identical committed operation first; check expected_revision and manifest hash; verify all referenced currently accepted inputs; validate the requesting exchange's prefix proof; append entries/roots and CAS active-decision projections; commit operation receipt and new session head atomically. Use the receipt authority in PREFIX_RECEIPTS.md for nonterminal stage provenance. It is not sufficient to store only a statement that the model “already saw” a child.

A stage prepared against revision 10 cannot silently apply at 12. Identical replay returns its original receipt even if later stages exist; a changed payload at the same expected revision is a new operation and must pass CAS. Crash before commit leaves the old head; crash after commit/before response recovers the old operation result, not a duplicate fragment. Multiple worker attempts cannot stage concurrently through a stale lease.

A validated fragment may be stored pending required prefix reconciliation, but may not advance the consumable session head until proof passes. Expose the pending operation distinctly, without skipping its journal position. A subsequent stage must not pretend a pending predecessor committed.

## SY-R05 — Small final seal and full canonical publication

`submit_file_synthesis` uses `$defs.SynthesisSeal`: contract, input_token, session_id, manifest_hash, expected_revision and journal_hash. It is a small identity-only terminal envelope; analytical content already lives in immutable, attributable fragments. With maximum field lengths its encoded size remains below 8192 bytes, independently of file/unit count. The 65536 limit is still enforced.

Before taking the final write lock, stream-validate the manifest, journal, active decisions, complete reference sets, accepted contribution and evidence closure, receipt lineage and required obligation coverage. Resolve current state and exact roots; do not use the latest manifest as a replacement. Produce a source-free prepared publication with all full canonical output fields computed from inherited mechanical manifest data plus explicit model decisions. The full internal canonical artifact may exceed the agent input cap; it is validated and written through existing paged storage/publication owners, not sent back through the provider.

In one authoritative transaction recheck task/input/session roots, every material acceptance generation, all required obligation keys and prepared-validation digest. Commit canonical file documents/evidence/knowledge/candidate-origin associations/coverage and the terminal operation outcome together. Seal the session against further stages. Do not expose partial complete-file coverage. Task terminal settlement still follows the full runtime/transcript finalization barrier; semantic publication and task completion are distinct milestones.

Material invalidation or graph-generation change rejects sealing with STALE_INPUT/MANIFEST_STALE (mapped to STALE_INPUT in the shared public error enum). Create a new session/manifest and explicitly adopt only independently revalidated decisions; do not edit the old manifest/root or carry its decisions forward blindly. Earlier valid child results remain their own artifacts.

## SY-R06 — Storage and liveness bounds

Use existing canonical/result storage plus `synthesis_manifests`, immutable `synthesis_manifest_items`, `synthesis_sessions`, `synthesis_entries` and an active-decision projection. These are tables/owners in ssr.db, not another database or service. Uniqueness: manifest/item key and ordinal; session/revision; session/set_key/page_index; session/current decision key. Preserve graph/candidate/evidence foreign keys and receipt references. A session's task/input uniqueness prevents duplicate active manifests for one input.

Validate manifest rows and journal pages in bounded memory (default 256 rows per host page). Do not materialize all child bodies or all staged deltas into a single Python dict just because the model now uses a small seal. Parameterize SQL; limit each statement's placeholders and use temporary prepared-ID tables in the same connection where needed. Host storage quotas are independently enforced and reported as incomplete capacity blockers, not silent item eviction. The default per-file synthesis journal allowance is 512 MiB; the manifest is separately accounted as required review metadata. Raising this allowance never increases the provider input cap.

A single rationale is bounded to 8192 characters and a stage to 65536 bytes; a huge argument is expressed through exact artifact/reference sets, not truncated. Insufficient total token/time/storage budget leaves a resumable session and an explicit limitation; it does not make an unrepresentable terminal payload the only possible completion path. The design guarantees bounded per-call encoding, not unlimited resources for arbitrarily large projects.

## Implementation order and tests

Extend canonical contribution preparation first; add frozen manifest/page retrieval; implement stage schemas, immutable journal/CAS/replay and prefix linking; implement streaming validation and small terminal seal; integrate the existing full-file commit owner. Remove the old provider-visible arrays instead of maintaining both terminal formats in new-mode runtime. Keep inherited semantic validators and evidence closure checks.
