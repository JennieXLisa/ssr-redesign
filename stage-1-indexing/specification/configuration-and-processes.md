# Configuration, capture manifests and process boundaries

This refines W01–W04's implementation inputs; it does not add another runtime or configuration framework. Public DTOs remain models.py; settings and semantic profiles are [settings.py](../contracts/v1/settings.py) and its generated settings.schema.json.

## File locations and merge rules

Installation settings live at `${XDG_CONFIG_HOME}/ssr/settings.toml`, falling back to `${HOME}/.config/ssr/settings.toml` on both macOS and Linux/WSL. Project settings live at `${SSR_STORAGE_ROOT}/projects/<project_uuid>/settings.toml`. Neither path is discovered by walking upward from a reviewed repository. Absent settings files mean an empty override; malformed/unreadable explicitly selected files are errors. `SSR_DATABASE_URL` and `SSR_STORAGE_ROOT` are the only SSR environment configuration overrides; neither is accepted in a target file or echoed into a diagnostic. Resolve storage root once at startup and reject a relative root. No DSN/password is serialized into a semantic fingerprint.

Merge shipped defaults → installation table → selected project table → explicit operation overrides. Tables merge recursively; scalar/array values replace completely; no list concatenation, interpolation, executable tags, includes, or environment substitution inside TOML. Unknown keys fail even in a lower-precedence table. Validate selected types and cross-field constraints after merging using Settings. The new error_response_target_bytes name deliberately replaces the contradictory hard-ceiling setting; no legacy alias is required for this unimplemented initial schema.

The profile selected by CreateIndexRequest.profile_path is a separate explicitly selected UTF-8 JSON file, not a target-discovered TOML settings file. SemanticProfile defines its exact fields, including language_overrides, encoding_overrides, package_roots, module_aliases, compilation_database, typed file_options and compiler_options. [Language profiles](language-profiles.md) specifies the exact defaults, fixture-to-runtime translation, per-file choice and extraction/resolution fingerprint projections. Fixture metadata is not passed directly to SemanticProfile or silently discarded. Unknown fields fail. The first matching language/encoding override wins; precedence order is semantic and must be hashed. Supported codec values are those in SourceUnit. Validate every snapshot path with the canonical path owner, including percent decoding, before access. An empty package root denotes the snapshot root. A compilation database is read only from that snapshot; profile selection never authorizes executing it.

Freeze parser/matcher/compiler/scanner versions, semantic overrides and sanitized compilation input as data when planning. Operational throughput, timeout and diagnostic settings do not rewrite semantic output identity. A timeout can be increased for retry of unchanged semantic inputs; a rule/encoding change creates another dataset.

## Exact capture manifest v1

The manifest is a JSON object with schema_version=1, snapshot_id, project_id, source_kind, sanitized source_locator, requested_revision, resolved_upstream_commit, options, entries, exclusions, submodules, and representation. All keys are present; unavailable scalar values are null. options is {fetch_submodules:bool, include_ignored:bool}. representation is {empty_directories_preserved:false, submodules_flattened:true, filters_applied:false}. OIDs use GitOid; identifiers use Id. No credentials or temporary filesystem path is permitted.

Each entries element is {file_id, path, path_digest, git_mode, blob_oid, content_digest, size_bytes, origin, link_target_hex, mapped_link_path}. path is the reversible canonical display path; path_digest hashes its decoded original bytes. git_mode is 33188/33261/40960. content_digest hashes the exact blob bytes, not decoded text. link_target_hex is lower-case hex for raw link bytes only for symlinks; otherwise null. mapped_link_path is the captured internal absolute-link mapping or null. origin is {kind, mount_path, upstream_commit, parent_pin}, with kind working_tree or fetched_commit; a local HEAD is provenance, never proof that working bytes match it. mount_path is empty for the root or the canonical child mount.

Each exclusions element is {path, reason, parent_mount, parent_pin, detail}; detail is sanitized explanatory text, not raw exceptions. Reasons are GIT_METADATA, MANAGED_STORAGE, IGNORED_UNTRACKED, SUBMODULE_NOT_FETCHED, or LFS_SKIPPED. Unsupported entry types are capture failures, not successful exclusions. Each submodules element is {mount_path, parent_mount, source_locator, parent_pin, local_head, resolved_upstream_commit, treatment}; treatment is working_tree, fetched_pin or excluded. All OIDs not established from actual metadata are null. This makes missing pin distinct from a guessed default branch.

Sort entries by original path bytes then file_id; exclusions by decoded path bytes/reason/parent_mount; submodules by decoded mount path bytes. Use storage.md's canonical JSON/SHA-256 algorithm and do not include manifest_digest inside its own hash input. Freeze the manifest before FINALIZING and store its digest alongside it. On recovery reconstruct the same exact object/ref/file census; never rebuild provenance from the current source checkout. An unresolved LFS pointer can be retained as raw representation, but the manifest must identify the unavailable underlying content as LFS_SKIPPED and the planner must not scan it as that content.

## Process runner contract

The injected runner accepts an absolute installed executable, an argv array, a harness-owned absolute cwd, a complete replacement environment mapping, optional byte-stream stdin, timeout/cancellation handle, and harness-owned stdout/stderr spool destinations. It returns exit status or a distinct start_failed/timed_out/cancelled termination plus complete output-spool paths and byte counts. It never takes a shell command string, shell=True, a target executable, or inherited environment as an implicit fallback. Complete large output is spooled; it is not silently truncated into a valid scanner/Git response. A spool/resource failure is explicit failed processing.

The owner supplies the operation-specific environment and verifies output framing/JSON. Target bytes appear only in stdin, separately validated operands after an option terminator where supported, or controlled source files. The runner does not guess compiler-option meaning; compiler-profile.md owns that grammar. [Native isolation](native-isolation.md) selects the macOS Seatbelt and Linux bubblewrap/Landlock/seccomp backends, exact resource policies, trusted launcher sequence, readiness gate and denial tests for compiler and scanner invocations. Git transport instead owns validated hostname/address pins and TLS configuration; it does not use the compiler/scanner no-network profile. Setting an environment variable alone is not a network-isolation proof. Scanner validation's offline policy requires an enforced no-network sandbox capability; doctor must fail that capability if it cannot actually prohibit a loopback connection in a controlled local test. Do not relabel a missing sandbox as successful offline validation.

On macOS/Linux/WSL, cancellation terminates only the child process group created for this invocation, waits for reap, and records cancellation. PID numbers from a previous process/boot do not authorize killing unrelated processes. No external process holds a database transaction open. Test the real Git/scanner runner path, not just that argv was assembled.

## Required doctor probes

Record a tool receipt containing absolute resolved tool path, exact version, executable SHA-256, tested capability, result PASS/FAIL/NOT RUN and sanitized diagnostic. Git must perform a real HTTPS fixture transfer with curloptResolve, TLS verification and redirect rejection; `git --version` alone proves none of those. PostgreSQL must answer server_version_num and allow a rolled-back test transaction against the configured database; do not apply migrations merely to probe it. Each grammar must load its declared capsule and parse a bundled valid/invalid snippet; W07–W11 additionally compile their packaged queries. regex/glob probes assert the documented matching behavior against fixed inputs. Semgrep must accept the exact scan argv from rules.md and produce parseable JSON on a harness-authored temporary fixture with version/network checks disabled; help output alone is insufficient. libclang must load the matching library and resolve a harness-authored declaration/reference without a build. No target code, build or provider call is a capability probe.

## Real HTTPS acceptance alongside deterministic fakes

W04 retains fake transport unit tests but G02 also requires a harness-owned loopback HTTPS Git smart-HTTP server, temporary CA, and tiny deterministic bare repositories. Only the test-injected address policy admits those exact loopback fixture endpoints; production public-address validation remains separately tested and has no CLI/environment bypass. Use the actual installed git-remote-https/libcurl path with the fixture CA, never disable certificate verification.

The server records requests. Assert exact default/tag/commit and immediate-parent submodule pins, no opted-out child/LFS request, rejected redirect with no destination request, certificate failure, pinned-address failure without DNS fallback, and absent Authorization/Cookie headers. Poison ambient credential helper/proxy/Git configuration in the test process and verify the replacement environment prevents use. Change injected DNS after validation and prove the actual connection still uses the approved pin. A real public smoke test is optional; the controlled real TLS transport test is mandatory and independent of mutable public branches. These tests are runtime gates, not executed by schema validation.
