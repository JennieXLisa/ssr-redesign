# Reference resolution and declaration/definition association

Implements S1-IX-R04, S1-FN-R06/R07, S1-RF-R01–R06 and S1-NV-R09. This is navigation binding, not attacker-input tracking, exploitability reasoning or automated taint analysis.

## Inputs, result shape and finality

Resolution consumes the complete successful extraction dataset for the selected snapshot plus its frozen resolver/compilation profile. Do not finalize a missing target while another required file is unparsed. Before this barrier, occurrences are readable with resolution pending. After it, each file's resolution work can publish independently.

A binding result carries reference ID, outcome `RESOLVED`, `AMBIGUOUS` or `UNRESOLVED`, zero/one/many target IDs as appropriate, producing backend/version, a closed basis code, and supporting source ranges or compiler identity. Work state is separate: pending processing is not UNRESOLVED. A recognized external API without captured target source is retained with external name/module context and `UNRESOLVED / EXTERNAL_SOURCE_NOT_CAPTURED`; never invent a readable local target ID.

Binding basis is the closed vocabulary in models.py: LEXICAL_DECLARATION, CAPTURED_IMPORT, DECLARED_RECEIVER_TYPE, CONSTRUCTOR_INITIALIZER, CLANG_REFERENCE, DYNAMIC_TARGET, MISSING_IMPORT, MISSING_BUILD_CONTEXT, UNSUPPORTED_BINDING, EXTERNAL_SOURCE_NOT_CAPTURED, CONTEXT_DISAGREEMENT and MULTIPLE_CANDIDATES. A new basis requires an explicit contract revision, not an arbitrary backend string.

For RESOLVED exactly one captured target is established. For AMBIGUOUS retain at least two distinct supported candidates with candidate-only presentation. One possible but unproven target remains UNRESOLVED with a diagnostic, not a proven binding. For UNRESOLVED retain the original expression and a reason such as DYNAMIC_TARGET, MISSING_IMPORT, MISSING_BUILD_CONTEXT, UNSUPPORTED_BINDING, or EXTERNAL_SOURCE_NOT_CAPTURED. A backend crash is a failed work unit, not one of these ordinary binding limitations.

## Portable source-backed resolution algorithm

1. Build indexed scope tables from published symbols and import occurrences. Search a reference's lexical scope outward; stop at the nearest applicable binding/shadowing declaration. A same-name function elsewhere in the repository is not automatically a candidate.
2. Resolve explicit local module imports only through captured files. Python relative/absolute imports search the captured package root and `__init__.py` boundaries; do not import code. JS/TS relative imports resolve the captured path using the fixed extension order `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, then corresponding `index` files; multiple equally permitted candidates are ambiguous. Record package-alias mappings from the selected captured configuration as data, never executing loaders. Lua literal `require` maps `a.b` to `a/b.lua` or `a/b/init.lua`; PHP namespace/use aliases map known declarations and literal include paths; Java import/package names map captured class declarations. External package source remains external.
3. Resolve direct calls to a unique visible declared callable when the language's scope rules support it. For languages with overloads, a name/arity match alone is only a candidate set unless the supported backend establishes the overload. Recursive calls use the same rules. Imports and callback arguments remain non-call reference occurrences.
4. Resolve straightforward receiver members from explicit declared receiver types, `self/this` ownership, or a direct constructor initializer in the same scope when there is no conflicting assignment/escape before the call. This last check is deliberately syntactic: any reassignment, branch-dependent assignment, address escape or unknown mutation invalidates this shortcut. Do not follow arbitrary value transformations, returns or containers to infer a type. Dynamic dispatch with multiple possible implementations is not one proven runtime target.
5. For C/C++, prefer compiler cursor references under the profile below. For unsupported reflection, macro-dependent target selection, function pointers without established binding, dynamic imports and dynamic shell command names, publish the honest unresolved/candidate result. Store the basis so future analysis can inspect the missing step.

Python, JS/TS, PHP, Java and Lua each own a small import/member policy module using the common scope/binding types. Shell resolution recognizes same-script function definitions and literal `source`/`.` links only when captured and with unambiguous scope; it does not simulate the shell. This finite algorithm is the required minimum and a permanent declared capability boundary, not a claim that parsing provides full language semantics.

## C/C++ compiler adapter

Use libclang cursor traversal for declarations, referenced declarations, type identity and USRs. Parse translation units from a managed read-only materialization of the captured snapshot. A captured `compile_commands.json` may provide argument arrays; otherwise use a recorded conservative profile (`-x c -std=c17` or `-x c++ -std=c++20` plus the captured root include path). Default-profile uncertainty remains in provenance. Headers are resolved in their recorded translation-unit contexts, not each treated as a universally standalone program. [S4–S5]

Never execute the compilation database's `command`. Prefer `arguments`; for a command-only entry tokenize as data with a documented platform parser, rejecting shell control operators/response files rather than executing them. Allow only language/standard/target, defines/undefines and include/search options needed for parsing. Remap source-local include paths into the snapshot. Reject plugins, forced arbitrary loads, output/action flags, driver executables, `@response` files and paths reaching outside the captured source or an explicitly installed standard-toolchain resource root. Record omitted/rejected options and their diagnostic effect. Do not generate compile databases by running target build scripts.

A compiler error affecting name/type binding means the affected reference remains MISSING_BUILD_CONTEXT or UNSUPPORTED_BINDING with diagnostics; do not promote guessed cursor data. A failure to start the installed compiler library or a worker crash is FAILED processing. System/toolchain headers may establish an external API identity but are never imported into the project's source namespace or returned as captured source. Compiler-resource versions and sanitized effective flags are part of the resolution fingerprint.

Map compiler source ranges to captured file IDs and raw-byte offsets, then match the structural occurrence by file/range/kind. Never use a line-only nearest-function match. If one macro expansion has no unique physical occurrence, preserve the reference and mark mapping ambiguity. Group translation-unit observations by physical reference ID. Agreement on one captured target establishes RESOLVED; disagreement across known build contexts yields AMBIGUOUS. Do not choose whichever worker finished first.

The required C++ fixture is `auto obj = new Test(); obj->something();` with Test declared in a captured header and its method defined in another file. It must open the member call and link its declaration/definition under the supported profile. Add overloaded methods, inheritance/virtual calls, two `Test` classes in different namespaces, reassignment before the call and missing headers. The first fixture must pass; the others must not create unsupported certainty.

## Stable identities and occurrence associations

Extraction gives every callable occurrence a durable provisional symbol ID and an own-source link. Keep those IDs valid after semantic association. Publish explicit SAME_ENTITY associations only when libclang USRs or an adapter's exact language identity rule establishes declaration/definition equivalence. Same-name overloads never merge by text alone. Connected proven associations form a display group; use the lexicographically smallest member ID as its representative in a given live view. Preserve all original IDs as valid aliases within that extraction dataset.

`find_functions` displays one item per established group with readable declaration/definition occurrence references. `read_function` validates the requested occurrence against either its own original symbol or a proven member association in the selected run. It never follows an ambiguous association. Once issued, a source token contains the original occurrence and source interval; a changing group representative does not redirect it. Merging groups during live indexing can change search representatives and ordering, so the already-agreed refresh rule applies. Freeze associations when the resolution dataset completes; fresh completed-run pagination is stable.

## Query ownership

Outgoing callees read call occurrences owned by the selected function and their bindings. Incoming callers join bindings targeting the selected identity/group to those same call occurrences. Return callsite IDs and exact argument/source references. Candidate-only relationships carry AMBIGUOUS, never an established caller label. Non-call references are separately queryable. A missing target name can be found through content/occurrence search but is not attached as a caller of every same-name function.

No whole-graph dump, graph database, mandatory compiler build, interpreter execution, or model-created binding table is introduced. Required capability tests and honest limitations are release gates, not optional examples.
