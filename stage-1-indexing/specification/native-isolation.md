# Native scanner and compiler isolation — v1

Owner: `processes.isolation` compiles trusted policy inputs; `processes.runner`
owns launch, pipes, cancellation and reap. W01 builds/packages its small native
launcher and probes the installed stack; W09/W13 exercise the real tools through
it. No source-controlled policy, environment, executable or resource discovery
is allowed. This is a concrete refinement of
[configuration-and-processes.md](configuration-and-processes.md), not a claim
that the production runner exists.

## Selected backends and installation gates

Native macOS arm64 uses the OS `/usr/bin/sandbox-exec -f POLICY EXECUTABLE ...`
Seatbelt backend, with the default-deny policy generated by
[`reference_isolation.py`](../validation/reference_isolation.py). Record the OS
build, executable SHA-256, policy version and denial-probe result. Apple's installed
`sandbox-exec(1)` manual marks this facility deprecated; availability is therefore
a **tested prerequisite**, not a promise of future OS support. Do not replace a
missing/rejected policy with unsandboxed execution or silently switch to a VM.
A future backend requires a reviewed policy revision and the same denial tests.

Linux x86-64 and Linux/WSL2 use non-setuid **bubblewrap 0.12.0 or newer**, enabled
unprivileged user namespaces, Landlock ABI **at least 3**, and libseccomp **2.6.x**.
W01 locks exact packages/hashes and builds the trusted `ssr-isolate` launcher
against the installed kernel UAPI and libseccomp. ABI detection, not a kernel
release string, is authoritative. Disabled user namespaces, missing LSM support,
blocked namespace creation in WSL/container policy, or a seccomp installation
error fails the capability. No host root/sudo, privileged service or Docker fallback.
Bubblewrap 0.12.0 is the selected floor because upstream documents a sandbox-setup
symlink fix there; `--not-a-security-boundary` is explicitly forbidden. [N1–N3]

These OS facilities are deployment dependencies, not Python parser dependencies.
The production distribution ships reviewed launcher source, reproducible build
instructions, native tests and installed artifacts for the declared architectures.
Compilation concerns only SSR's own helper, never the research target.

## Trusted launch input and resource inventory

The runner takes `IsolationInputs` with platform, purpose (`compiler` or
`scanner`), snapshot, resources, runtime, control, scratch and exact executable
files. All roots are disjoint, canonical absolute native paths. Before policy
construction, the materializer opens roots/ancestors no-follow, verifies regular
files and immutable digest inventories, and rejects symlinks or untrusted writers.
The pure model checks lexical shape/overlap only; it cannot certify filesystem
ownership or prevent native races. Job roots live under a private, researcher-owned
0700 directory. Never bind the user's HOME, checkout, database directory, whole
SSR storage root, `/`, `/opt/homebrew`, `/usr`, `/etc`, or an ambient SDK tree.

| Resource | Read | Write | Execute/load |
|---|---|---|---|
| Snapshot / scanner batch input | Exact included data, verified read-only tree; no host fallback | Never | Never |
| Pinned compiler resources | Explicit frozen header/resource census only | Never | Never |
| Runtime capsule | SSR worker, Python/stdlib/extensions, pinned libclang or scanner and audited dependencies; no credentials or project data | Never | Exact executable census; native code only from runtime/OS code roots |
| Control | Frozen job JSON, effective rule files and launcher policy; no DSN, keys, source-discovered settings | Never | Never |
| Scratch | Scanner-only private temporary/cache data | Scanner only | Never |
| Parent output spools | Worker receives anonymous stdout/stderr pipes, not host spool paths | Parent writes; worker only sends pipe bytes | Never |

On macOS the additional fixed OS code/read trees are the `MAC_SYSTEM_ROOTS`
constant in the reference policy. They contain necessary OS runtime files, not
captured source; their content/version is recorded with the OS build. The allowed
`/dev/null`, `/dev/random` and `/dev/urandom` files are explicit. Ancestor **metadata**
lookups are permitted only to reach approved roots. The dyld startup exception
allows reading the **root directory itself** (`literal "/"`, not `subpath "/"`)
and two exact sysctls, `security.mac.lockdown_mode_state` and `kern.bootargs`.
It does not permit reading child file contents. These requests were identified
from kernel denial records after the first native probe aborted before main;
root entry names are a disclosed metadata exposure, not hidden full-filesystem
access. There is no global file-read grant. An OS path alias must be verified as the same trusted OS resource before
being added in a reviewed revision; an arbitrary symlink is not authority.

The Linux x86-64 profile selects a glibc runtime capsule, including its dynamic loader and dependency closure at
known internal paths, not a bind of the entire host OS. W01 inspects SSR's own
ELF metadata without running `ldd` on reviewed files. Copy verified regular
runtime artifacts into an immutable installation tree. Preserve the interpreter
layout and use an SSR launcher linked to its packaged loader/RPATH; install the
fixed interpreter at `/lib64/ld-linux-x86-64.so.2` by a read-only bind from the
capsule's `/runtime/lib/ld-linux-x86-64.so.2`. Reject ELF tools naming a different
interpreter in this profile; musl is not an untested implicit alternative. The
replacement environment sets the trusted literal `LD_LIBRARY_PATH=/runtime/lib`
for the packaged dependency closure; it never inherits a host loader path. These exact
runtime paths and file digests are part of the installation receipt. Do not expose
an arbitrary host file merely because a loader error names it.

## Linux launch sequence and policy

`linux_policy()` provides the exact mandatory namespace/mount argv. It creates
user/PID/network/IPC/UTS namespaces, maps the unprivileged caller to namespace
UID/GID 0, sets a new session and dies with its parent. Only the trusted launcher
temporarily receives namespace-scoped CAP_SYS_ADMIN and CAP_SETPCAP, to seal
mounts; **no target-reading worker retains either capability**. No `*-try` namespace
option, `--share-net`, host socket mount, broad host bind or inherited environment.
Mount runtime, snapshot, control and numbered resources read-only at `/runtime`,
`/snapshot`, `/control`, `/resources/N`; create private `/scratch`, `/proc` for the
PID namespace and minimal `/dev`, plus the single ELF interpreter bind above;
remount root read-only. The host scratch path
is not bound. Namespace setup happens before the worker is permitted target data.

The trusted `/runtime/bin/ssr-isolate --policy /control/launcher.json` performs:

1. Read only the parent-generated bounded launcher JSON specified below. Verify
   its digests, selected fixed worker and installation. Close every inherited
   descriptor except stdin/stdout/stderr: anonymous pipes or `/dev/null`, never
   sockets, directory descriptors, database connections, live source handles or
   host-writable regular files. Change cwd to `/snapshot`. Verify `/proc/self/ns/user`
   and `/proc/self/ns/mnt` inode identities differ from the recorded parent's.
   Reject a setuid/root-host launch; UID 0 is permitted only inside the new namespace.
   Use `mount_setattr` with AT_RECURSIVE and zero-filled mount_attr to add
   MOUNT_ATTR_NOEXEC|MOUNT_ATTR_NOSUID|MOUNT_ATTR_NODEV on **every** noexec_mounts
   path (`/snapshot`, `/control`, `/scratch`, `/resources/N`); attr_clr is zero,
   so existing read-only restrictions stay set. Check every return, then verify
   mountinfo and statvfs flags. This prevents scanner executable mappings from
   data/scratch, which Landlock EXECUTE alone does not prevent. Denied/missing
   mount_setattr or verification is failed isolation, not a softer fallback. [N6]
   Set and lock SECBIT_NOROOT, SECBIT_NO_SETUID_FIXUP and
   SECBIT_NO_CAP_AMBIENT_RAISE; clear/lock KEEP_CAPS. Clear ambient capabilities,
   drop every bounding-set capability while CAP_SETPCAP is available, then clear
   effective/permitted/inheritable sets with capset and verify all are empty.
   All this happens before processing any reviewed input. The recipe deliberately
   does not request bubblewrap's `--disable-userns` nested-user-namespace mode,
   which would complicate mount ownership before sealing. After sealing, seccomp
   blocks unshare/setns and all CLONE_NEW* flags, preventing worker namespace
   creation; no capabilities can be regained across exec. [N7]
2. Query `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)`;
   fail below ABI 3. Set `handled_access_fs` to **every** right through TRUNCATE
   listed in `HANDLED_FS`. Add PATH_BENEATH rules from `landlock_rules` using
   verified O_PATH descriptors. READ_FILE/READ_DIR on data/control/runtime;
   EXECUTE only on exact trusted binaries, not whole data or scratch trees;
   scanner scratch gets exactly `SCRATCH`, never EXECUTE/MAKE_SOCK/device rights.
   Call `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)` then
   `landlock_restrict_self`; close all rule/root descriptors. No ABI downgrade.
3. Build libseccomp with default ALLOW and bad-architecture KILL_PROCESS. Support
   native x86-64 only, not x32/compat ABIs. Add EPERM rules for every syscall in
   `DENY_SYSCALLS`; absence of a named syscall in the locked architecture table is
   a packaging error. Deny `clone` when any CLONE_NEW* namespace flag is set.
   Return ENOSYS for `clone3` so libc can use filtered `clone`; normal fork/thread
   creation remains possible. `socketpair(AF_UNIX, ...)` is allowed for private
   worker IPC, but `socket`, connect/bind and message socket operations are denied.
   Pipes, not SCM_RIGHTS, carry SSR results. Load the filter; check every return.
4. Exec only the selected packaged worker, with a complete replacement environment.
   The compiler worker preloads its Python extension/stdlib dependency closure
   and the pinned libclang library **before reading source**. It then installs a
   second seccomp filter with TSYNC (failure is fatal): EPERM for execve/execveat,
   mmap with `prot & PROT_EXEC`, mprotect with `prot & PROT_EXEC`, and
   pkey_mprotect with `prot & PROT_EXEC`. This forbids late native code loading;
   missing preload dependencies fail visibly rather than reopening loader access.
   AST parsing needs no JIT. Scanner workers retain only the executable census
   needed for the pinned scanner subprocess path; no arbitrary shell is shipped.
5. Emit readiness with installation/job/launch/policy digests only after all required seals are active.
   The parent then streams the sanitized job or releases its input gate. A worker
   exit, timeout, unsupported policy, missing readiness or digest mismatch fails
   startup. No compiler observation/scanner match from that attempt is publishable.

Landlock controls file operations/exec, not interpretation by Python or every
executable-memory operation. Verified noexec data mounts apply to both purposes;
the compiler's second seal additionally closes late native loads;
the trusted worker's data-only API, `python -I -S`, fixed import paths and no
eval/import of target files remain mandatory. No claim is made that a mount
namespace alone enforces these properties. TCP-only Landlock rights would not
provide the required UDP/Unix prohibition, hence the socket seccomp policy. [N2–N4]

## Complete launch envelope and readiness

`NativeLaunch` is the strict frozen launch input in the reference. It requires
typed IsolationInputs, the actual installation-census SHA-256 and canonical
sanitized-job SHA-256. Linux additionally requires the parent user/mount namespace
inode identities, read before launch; macOS requires both null. The selected
worker is fixed by purpose: `<runtime>/bin/ssr-compiler-worker` or
`<runtime>/bin/ssr-scanner-worker`, and must be in the executable census. No free
command string, arbitrary Python script, `-c` argument or user-selected executable
is part of this interface. These packaged SSR bootstrap workers alone consume
job JSON and launch installed tool components.

`launch_envelope()` supplies the entire launcher.json projection: schema_version,
policy_version, platform, purpose, installation_digest, job_digest, worker_argv,
parent_namespaces, environment, policy, policy_digest and launch_digest. The
argument tail is fixed `--launch <control>/launcher.json`; Linux paths are mapped
to `/runtime` and `/control`. policy_digest hashes the complete platform policy;
launch_digest hashes all other envelope fields, excluding itself. These physical
launch hashes are audit receipts, not dataset semantic fingerprints. The parent
writes canonical JSON to an exclusive 0600 control file. The native helper/worker
validates exact keys, nulls, digest reconstruction and the fixed worker, rather
than accepting an incomplete policy dict as an envelope. Bound launcher JSON to
1 MiB; excessive policy inventory is an explicit configuration/resource failure.
Source bytes are not embedded in the envelope.

The fixed worker emits exactly the canonical JSON from `expected_ready()`, followed
by one newline, as the first stdout record, at most 2,048 bytes. The parent
validates it with `validate_ready()` before releasing job input. This binds
purpose, installation, policy, launch and job identity and avoids an undocumented
extra inherited descriptor requirement. Tool stdout follows that single framing
line unchanged and is spooled by the parent; stderr remains a separate pipe.
Duplicate/extra fields, wrong digests, oversized/missing newline, failure before
positive startup, or timeout fails the launch. The compiler worker emits READY
only after its second seal. The scanner worker emits READY after its first seal
and before accepting a sanitized scan request. Job bytes must hash to job_digest;
changing requests requires a new envelope, not reusing old readiness.

The pure envelope tests prove serialization/identity checks only. The complete
Linux helper and production worker handshake still require W01 native tests.

## macOS runner integration

Generate the SBPL from verified inputs, write it exclusively into the private
control directory, then invoke `/usr/bin/sandbox-exec` with an argv array and
`-f` (not a shell or a target-supplied profile). `seatbelt_policy()` is the literal
policy recipe: default deny; exact read trees; exact executable files; executable
mapping only from trusted runtime/OS trees; scanner scratch-only writes; no
network allowance, Mach service lookup, sandbox extension, global home grant or
wildcard process execution. Children inherit the same restrictions.

The complete environment is `replacement_environment()`: no inherited PATH,
proxy/SSH/credential variables, PYTHONPATH, DYLD_*, LD_*, CPATH, SDKROOT,
LIBRARY_PATH or compiler config overrides. Invoke Python with `-I -S` and supply
its fixed SSR import root from trusted bootstrap code. Locate semgrep-core by its
verified absolute path. Extra native startup needs require a reviewed exact
allowance and rerun of every denial test, not iterative broad `allow default`
policies. The deprecated backend's future removal is an explicit unsupported
installation result; it never authorizes an unsandboxed run.

## Doctor and acceptance matrix

Before admitting work, doctor uses owned fixtures and this same runner/policy to
prove allowed operations **and** denials. A child that never reaches its positive
control has failed startup, not passed containment. Denials must be EACCES/EPERM
at the tested operation; ENOENT, ECONNREFUSED, timeout or child crash is not proof.
On Linux verify actual namespace identities, loaded seccomp and Landlock ABI;
on macOS verify sandbox startup and the policy digest. Use a real parent-owned
listening socket for a loopback control; never contact an external service.

Mandatory tests: read captured and installed resource fixtures; read denied host
sentinel, sibling project and parent-spool paths; deny outside directory listing;
deny absolute and symlink escape reads; deny writes/truncation to snapshot/runtime
and host sentinel; permit scanner scratch writes only; deny data/scratch exec;
deny compiler late executable mapping; deny IPv4/IPv6 TCP, UDP and host Unix
socket access; repeat denied reads/network in forked children; reject ambient
credentials/SDK/plugin variables and non-inventory executables; reject unsupported
OS/ABI and failed readiness; cancellation reaps only the created process group.
Then run actual Semgrep fixture validation/scan and libclang header/reference
probes with the identical installed policy. Missing tool integration is NOT RUN.

The opt-in native smoke command is:

```sh
python3 -B stage-1-indexing/validation/probe_macos_isolation.py --run
```

It builds only the included trusted C probe in disposable owned storage, not
reviewed source. Its JSON receipt is separate from pure policy regressions and
from production doctor/tool gates. The ordinary specification suite does not
claim native enforcement or auto-run native compilation. Linux launcher/native
integration remains a separate mandatory platform gate until actually executed.
